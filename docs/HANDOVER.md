## 3. 서버 설정값 (이름만 — 값은 회사가 보관)

| 이름 | 뜻 | 주의 |
|---|---|---|
| `NEXT_PUBLIC_DATA_MODE` | `live` = 실제 운영 | 빌드할 때 반영됩니다. 바꾸면 다시 배포해야 합니다 |
| `DATABASE_URL` | Supabase DB 연결 문자열 | **서버 전용**. 외부에 노출되면 즉시 DB 비밀번호를 바꿉니다 |
| `SETUP_CODE` | 최초 설정 화면을 여는 코드 | 최초 설정 뒤에는 지워도 됩니다 |
| `DB_POOL_MAX` | DB 연결 수 (선택) | 기본값으로 충분합니다 |
| `VAPID_PUBLIC_KEY` · `VAPID_PRIVATE_KEY` · `VAPID_SUBJECT` | 휴대폰 알림 키 (`npm run vapid`로 생성) | 개인 키는 **서버 전용**. 다시 만들면 모든 직원이 알림을 다시 켜야 합니다. 없으면 알림만 꺼지고 나머지는 동작합니다 |

**배포 전 자동 점검**: `npx vercel env pull .env.preflight` → `node --env-file=.env.preflight scripts/preflight.mjs`.
- 운영 모드, 연결 문자열(풀러·SSL), 공개 변수 비밀값, 설정 코드, DB 스키마·**RLS**를 확인합니다. ❌가 없어야 배포합니다.
- `.env.preflight`는 비밀값이 들어 있으므로 확인 후 지웁니다. 저장소에는 올라가지 않게 설정돼 있습니다.

**코드를 바꾼 뒤 배포 전**: 로컬·테스트용 Postgres 주소로 `TEST_DATABASE_URL=postgres://… npx vitest run`을 돌립니다(테스트가 임시 DB를 스스로 만들고 지움 · 운영 DB 주소는 넣지 마세요). 내장 DB(PGlite)에서는 통과해도 실제 Postgres에서만 생기는 오류가 두 번 있었습니다(D-41 데이터 이중 저장, D-42 동시 첫 시작 충돌).

**배포 직후**: `npm run smoke -- https://배포주소`를 돌립니다(D-44). 로그인하지 않고 공개 주소만 확인하며 회사 데이터를 읽거나 바꾸지 않습니다.
- 확인하는 것: 운영 모드·DB 연결·스키마, 보안 헤더(CSP·HSTS 등), 로그인 없이 데이터·백업·쓰기 차단, 다른 사이트 요청 차단, 최초 설정 코드, 알림 키, 홈 화면 앱 파일
- ❌가 하나라도 있으면 종료 코드 1입니다. 고친 뒤 다시 돌립니다.
- 외부 감시 서비스에는 `/api/health`를 등록하면 장애를 알림으로 받을 수 있습니다.

AI API 키는 현재 쓰지 않습니다. 위험 분석은 규칙 기반이며 AI 연결은 대표 승인 후 별도로 진행합니다.

## 4. 백업과 복구

| 방법 | 들어가는 것 | 주기 | 담당 |
|---|---|---|---|
| 앱 **자료 이관·점검 → 전체 자료 내려받기** (JSON) | 현장·원가·기성·변경공사·출퇴근·보고·작업 인원·지시·요청·이력. 사진 원본·비밀번호는 제외 | 월 1회 (월말) | 대표 |
| Supabase 자동 백업 | DB 전체 (사진 원본 포함) | 요금제에 따라 매일 | 자동 (요금제 확인) |
| 수동 DB 백업 (`pg_dump`) | DB 전체 | 분기 1회 · 큰 변경 전 | 시스템 관리자 |

- **복구는 DB 백업으로 합니다.** 앱에서 내려받는 JSON은 보관·열람·이관용입니다. 아직 앱 안에서 JSON으로 되돌리는 기능은 없습니다.
- 잘못 넣은 엑셀 자료는 7일 안에 **자료 이관·점검 → 최근 가져오기 → 가져오기 취소**로 되돌립니다.
- 원가 한 건은 현장 상세 → 원가에서 무효 처리합니다.
- 활동 이력(누가·언제·무엇을)은 지워지지 않습니다.

## 6. 개인위치정보 (출퇴근 GPS)

- 위치는 **출근·퇴근·보고를 누를 때만** 한 번 기록합니다. 처음 출근할 때 동의 화면이 나오고, 동의 기록(시각·문구 판)이 남습니다.
- 위치 기록은 대표·관리자만 봅니다. 현장 직원은 자기 기록만 봅니다. 발주처에는 보내지 않습니다.
- **회사가 정할 것**(별지 제5호) — 법률·노무 전문가와 확인 후 대표가 **운영 관리 → 개인위치정보**에서 설정합니다(D-43):
  - **보관 기간**: 지나면 좌표·거리·오차를 매일 자동으로 지웁니다. 출퇴근 시각과 현장 안/밖 판정은 근무 기록으로 남습니다. 정하기 전에는 지우지 않고 화면에 경고가 뜹니다.
  - **좌표를 볼 수 있는 사람**: 대표만 / 대표·관리자. ‘대표만’이면 서버가 관리자에게 좌표를 아예 보내지 않습니다.
  - **고지 문구**: 같은 화면 ‘직원에게 알리는 내용’에 직원이 보는 문구가 그대로 나옵니다. 고쳐야 하면 미래AI랩에 요청합니다(문구 판이 올라가 다시 동의를 받음).
  - 위치정보 관련 신고·등록 필요 여부 (전문가 확인)
- **직원 열람·철회**: 직원은 휴대폰 ‘내 정보 → 내 위치 기록’에서 자기 기록을 보고 ‘위치 기록 그만두기’를 누를 수 있습니다. 누르면 남은 좌표를 바로 지우고, 출퇴근은 ‘위치 없음’으로 계속됩니다.
- **동의 기록**: 동의한 시각·문구 판·그때 알린 보관 기간·열람 범위가 남습니다. 회사가 조건을 직원에게 불리하게 바꾸면(더 오래·더 많은 사람) 다음 출근 때 다시 동의를 받습니다.
- **퇴사·본인 요청**: ‘직원별 동의 현황’에서 ‘좌표 지우기’(사유 기록, 되돌릴 수 없음). 규칙 변경·삭제는 모두 활동 이력(종류: 개인위치정보)에 남습니다.
- 활동 이력 문구에는 거리·오차를 쓰지 않습니다(좌표를 지워도 문구로 위치가 남지 않게).

## 6-1. 데이터가 쌓였을 때 (성능)

- 1년치(현장 6곳·직원 20명, 약 3.4만 건)에서 명령 1건이 약 0.5초 걸립니다. 현장 휴대폰은 최근 60일만 받습니다(압축 약 17KB).
- 약 2년치(주요 기록 4.5만 건)부터 느려지기 시작합니다(3년치 측정 1.6~1.8초).
- 그 시점이 되면 **자료 이관·점검 → 데이터 규모**가 노란색 경고로 바뀝니다. 이때 ‘오래된 기록 보관 정리(아카이브)’ 작업을 유지보수로 진행합니다(D-34).
- 측정 방법: `npm run perf` (3년치는 `PERF_DAYS=900 npm run perf`).

## 7. 문제가 생겼을 때

| 증상 | 먼저 확인 | 다음 |
|---|---|---|
| 한 사람만 로그인이 안 됨 | 사용자 화면에서 잠김·비활성 여부 | 비밀번호 초기화 |
| 모두 접속이 안 됨 | `/api/health`, Vercel 배포 상태, Supabase 상태 페이지 | Vercel 최근 배포 로그 → 직전 배포로 되돌리기 |
| 누가 바꿨는지 확인 필요 | **활동 이력** (기간·사람·종류로 검색, CSV) | 해당 화면에서 되돌리기·정정 (사유 기록) |
| 화면은 뜨는데 저장이 안 됨 | 인터넷 연결, Supabase 사용량 한도 | 현장 보고는 휴대폰에 남아 있어 연결되면 다시 보냅니다 |
| 숫자가 장부와 다름 | 자료 이관·점검의 빠진 자료, 잔여예상원가 재추정일 | 공무 확인 대기 원가가 남았는지 확인 |
| 위치가 계속 ‘현장 밖’ | 현장 위치·반경 | 큰 현장은 반경을 넓힙니다 |

유지보수 범위(무상 기간·응답 시간·추가 개발)는 계약서를 따릅니다.

## 8. 보안 수칙

1. `DATABASE_URL`·Supabase 키를 메신저·메일로 보내지 않습니다.
2. 퇴사자는 당일 비활성화합니다. 대표 계정은 공유하지 않습니다.
3. 발주처 계정에는 그 발주처 현장만 연결합니다. 포털에는 내부 원가·이익·미수가 서버에서 차단되지만, 연결 현장을 잘못 고르면 다른 현장의 진행률이 보입니다.
4. 엑셀 자료를 올린 뒤 원본 파일은 회사 보관 폴더에만 둡니다.
